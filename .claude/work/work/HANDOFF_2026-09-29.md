## 8. Idempotency / concurrency (do not regress)

- **Create** (`POST /orders`): `apps/mobile/src/ui/new-order-screen.tsx`
  keys `clientRequestId` off a hash of the outgoing payload
  (`requestIdRef`), re-minting it only when the payload actually changes —
  this was a real bug found and fixed in Slice 1 (previously one key per
  screen instance, causing a permanent `idempotency_conflict` after a
  failed-then-edited retry). Mirrors `apps/web/src/routes/order-editor.tsx`.
- **Replace** (`PUT /orders/{id}`): uses `expectedVersion` optimistic
  concurrency, never sends/reuses the create idempotency key. Confirmed by
  Slice 2's review as matching web exactly, including reload-on-conflict
  (never silent overwrite).
- The MOB-4a checkpoint commit did not touch this logic — confirmed by
  reading the diff before committing.

## 11. Known-flaky tests (history, now believed stable — watch on next change)

`apps/mobile/src/ui/new-order-screen.test.tsx` was flaky earlier today:
7 of 10 tests failed in a full sequential `jest` run, but every test
passed in isolation. Root-caused (by `mobile-engineer`, independently
confirmed by `code-reviewer`) to React Native's `VirtualizedList`
internal `setTimeout`-driven cell update not being fully cancelled on
unmount, colliding across many mount/unmount cycles of `FlatList`-based
pickers within one test file — a harness/library interaction (`react@
19.2.3` + `react-reconciler@0.34.0` + `react-native@0.86.3` +
`jest-expo@~57.0.5` + `@testing-library/react-native@14.0.1`), not an
application bug. Fixed with a shared `pressAndSettle`/`longPressAndSettle`
+ `afterEach` settle-timer helper, now reused across every new mobile UI
test file. Verified stable across 5+ consecutive full-suite runs today.
**If this recurs after a future change to these test files, don't
re-diagnose from scratch — read this section first**, and consider
splitting a growing test file rather than adding more scenarios to an
already-large one.
