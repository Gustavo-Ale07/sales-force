P-08 · P-21 · STACK-6SYNC-1 · SYNC-2 · SYNC-3 · DATA-3V-07

Marca d'água segura SYNC-2 V-07

A spec usava change_seq de sequência global, que pula linhas em transações concorrentes (R01). Proposta: carimbo xid8 + janela até pg_snapshot_xmin, provada por teste de transações concorrentes (V-07). Transações longas em tabelas sincronizáveis são proibidas.

Ordem de processamento de uma janela SYNC-3

  1. resync_required → descarta datasets sincronizados (nunca a outbox) e faz carga inicial.
  2. left conta → bundle_delete(account_id); left registro → apaga o registro.
  3. entered conta → bundle completo dentro das janelas de retenção; entered registro → o registro.
  4. Resync de dataset de referência → substituição completa.
  5. Upserts, deletes e tombstones regulares filtrados pelo escopo atual.

Toda tabela sincronizável por conta tem account_id não nulo — é o que torna o bundle calculável.

Contratos forma proposta

GET /sync/pull?cursor=&limit=
200 {
  changes: [ upsert | delete | bundle_delete |
             record_delete | dataset_reset |
             resync_required ],
  cursor:  <opaco>,
  has_more: boolean
}

Cursor opaco: versão do protocolo, W_prev, W_now fixo da janela, chave de continuação. Abaixo da versão mínima → "atualização obrigatória" (política R11).

POST /sync/push
commands: [{
  command_id: UUIDv7,   // idempotência
  entity_id:  UUIDv7,   // registro afetado
  type, payload,
  client_created_at     // informativo
}]
→ por comando: accepted | rejected | needs_review

UUIDv7 mais de 1 dia no futuro é rejeitado; regra de negócio nunca ordena por identificador (DATA-3, proposto). Ordem e dependência entre comandos R06; nomes finais R09.

Banco local e versões

  • Datasets sincronizados são caches descartáveis; outbox (e rascunhos, se locais) é o único dado não reconstruível.
  • Migração local com outbox pendente sob OTA R10. Regra interina PROPOSTA: mudança de schema local ou de protocolo só em novo binário com versão de protocolo incrementada.
  • PROPOSTO (R11): versão do protocolo no cabeçalho, independente de binário e bundle; servidor aceita N e N-1; painel de aparelhos por versão.

Testes obrigatórios sync-protocol §11

  • Watermark: transações concorrentes confirmando fora de ordem; nenhuma linha pulada (V-07).
  • Espelho: linhas inalteradas não recebem novo carimbo.
  • Escopo: reatribuição → bundle ao novo dono, bundle_delete ao anterior; atendente; equipe → resync_required.
  • Autorização: pull nunca devolve fora do escopo; nenhum custo/margem em dataset.
  • Push: replay do mesmo command_id; revalidação de preço, alçada, crédito.
  • Aparelho pending/revoked sem dados; carga inicial retomável.
