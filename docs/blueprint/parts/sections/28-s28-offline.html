Offline

P-07 · P-08 · P-09 · STACK-6 · SNK-4SYNC-1…3 · MOB-2 · AUTH-2

O aparelho guarda uma cópia filtrada e descartável dos dados autorizados, mais os seus próprios comandos pendentes. O servidor é a autoridade: revalida cada comando e decide o que o aparelho pode ver.

Aparelho pending ou revoked: pull e push recusados, nenhum dado de negócio (AUTH-2, PROPOSTO). Revogado: o app apaga banco local e arquivos.

Nunca no aparelho: custo, margem (P-20/P-23), dados fora do escopo (P-21), credenciais de servidor (P-22).

Cenários

1 · Sincronização normal SYNC-2

  1. Gatilho: app aberto, conexão voltou, 15 min em primeiro plano, manual ou após salvar pedido.
  2. Push dos comandos pendentes (nenhum).
  3. Pull a partir do cursor: janela de transações já concluídas.
  4. Aplica mudanças; "sincronizado às 10:42".

2 · Pedido offline P-08

  1. Sem sinal: pedido montado com dados da última sync.
  2. Comando createOrder na outbox local; tela "salvo offline".
  3. Conexão volta → push; servidor revalida tudo.
  4. accepted → aprovado ou aguardando aprovação → outbox de integração → Sankhya.

3 · Retry STACK-6 · SNK-4

  1. Worker tenta incluir pedido; Sankhya responde erro temporário.
  2. Outbox registra tentativa e próximo horário (backoff; até 8 tentativas — RF-SNK-3).
  3. Antes de reenviar, verifica o campo de origem com o UUID do pedido.
  4. Não existe → inclui; existe → vincula sem duplicar.

4 · Comando duplicado P-08

  1. Push enviado; conexão cai antes da resposta.
  2. App reenvia o mesmo lote na próxima sync.
  3. Servidor encontra o resultado armazenado para o command_id.
  4. Devolve o mesmo resultado; nenhum pedido duplicado.

5 · Conta sai da carteira SYNC-3 R06

  1. Gerente transfere a conta para outro vendedor; eventos left/entered na mesma transação.
  2. Pull do vendedor anterior recebe bundle_delete: conta e dados filhos apagados do aparelho.
  3. Comando pendente para a conta → rejected com motivo (PROPOSTO).
  4. Novo dono recebe o bundle completo da conta.

6 · Preço mudou P-09 R33

  1. Pedido criado offline com preço antigo.
  2. Tabela de preço mudou no Sankhya e chegou ao espelho.
  3. Push → needs_review; pedido em revisao_preco.
  4. Vendedor vê anterior × atual e confirma ou edita; alçada reavaliada.

7 · Aparelho revogado RF-IAM-7 AUTH-2

  1. Admin revoga o aparelho; sessões invalidadas imediatamente.
  2. Próximo contato: API recusa com status "revogado".
  3. App apaga banco local e arquivos; comandos não enviados são perdidos (R08 reduziria).
  4. Se nunca reconectar: bloqueio após 7 dias sem sync; limpeza é melhor esforço (risco aceito).

8 · Limite offline RF-IAM-8 R16

  1. Aparelho sem sincronizar há mais de 7 dias (configurável).
  2. App bloqueia o uso até sincronizar; outbox preservada.
  3. Relógio adulterado: PROPOSTO guardar hora do servidor da última sync, detectar volta no tempo, usar tempo desde o boot.
  4. Sync bem-sucedida desbloqueia.
